# MatrixChatBridge 0.4.9 管理员操作手册

简体中文 | [English](administrator-manual-0.4.9.en.md)

机器人迁移到独立 VPS、配置 WSS 反向代理或在一台主机运行多个 Minecraft
服务端时，请同时参阅
[跨 VPS 与多服务端部署指南](跨VPS与多服务端部署指南.md)。

本文统一把安装在 Leaf/Paper 中的 Minecraft 插件称为“插件端（前端）”，把
Docker 中运行的 Python Matrix 机器人程序称为“机器人后端（后端）”。Matrix
Homeserver 是外部聊天平台，不称为本项目后端；Matrix 中的机器人用户称为
“机器人账号”。

本文供 Minecraft 服务器与 Matrix 房间管理人员使用。文中的 token、密码、
验证码均为示例，不要把真实 token 发到聊天室、群公告或工单中。

## 1. 基本信息

| 项目 | 当前值 |
|---|---|
| 后端 SSH 地址 | 以本地 `deploy.local.psd1` 为准 |
| SSH 用户 | 以本地 `deploy.local.psd1` 为准 |
| SSH 端口 | 以本地 `deploy.local.psd1` 为准 |
| 后端目录 | `/opt/matrix-serverchat` |
| Matrix 机器人 | 以机器人后端 `.env` 为准 |
| Matrix 房间 | 以机器人后端 `.env` 为准 |
| Matrix homeserver | 以机器人后端 `.env` 为准 |
| 后端协议 | v2 |
| 插件版本 | 0.4.9 |
| Java 版本 | 21 |

0.4.9 的后端与插件应同时升级。v2 后端不会接受旧版 v1 插件。

## 2. 管理职责

### Minecraft OP 或服务器控制台管理员

- 修改插件 `config.yml`；
- 生成服务器独立 token；
- 重载桥接或重启 Minecraft；
- 查看插件连接状态。

### Matrix 房间管理员

- 查看服务器状态；
- 设置显示名称和展示端口；
- 调整路由组；
- 启用或禁用服务器；
- 查看管理审计记录。

机器人采用双重鉴权。管理员必须同时满足：

1. 完整 Matrix ID 已登记在机器人本地管理员表中；
2. Matrix 房间权限等级达到 `ADMIN_POWER_LEVEL`，默认是 `50`。

房间昵称、普通游戏账号绑定和消息中手写的 Matrix ID 都不能取得管理权限。
即使是房间权限等级 `100` 的成员，未登记时也不能使用 `!server` 或
`#server`。

### 后端主机管理员

- 部署和更新 Docker 后端；
- 从服务器控制台登记第一名 `owner`；
- 首次登记服务器 token；
- 轮换 token；
- 备份数据库和查看日志。

## 3. 插件配置

配置文件通常位于：

```text
<Minecraft服务端目录>/plugins/MatrixChatBridge/config.yml
```

关键配置示例：

```yaml
bridge:
  enabled: true
  url: "ws://127.0.0.1:8766/minecraft"
  server-id: "survival"
  server-name: "生存服"
  relay-group: "main"
  game-port: 25565
  token: "服务器自己的64位token"
```

字段说明：

- `url`：机器人后端地址。同机可使用 `ws://127.0.0.1:8766/minecraft`；
  可信局域网可使用例如 `ws://192.168.1.10:8766/minecraft` 的内网地址
  （未加密，仅限受控网络）；跨公网或不可信网络必须通过 TLS 反向代理使用
  `wss://`。跨机器部署详见[跨 VPS 与多服务端部署指南](跨VPS与多服务端部署指南.md)。
- `server-id`：稳定且唯一的服务器 ID，只使用字母、数字、点、下划线或连字符。
- `server-name`：插件上报的默认中文显示名称。
- `relay-group`：聊天路由组；同组服务器互相转发玩家聊天。
- `game-port`：Minecraft 游戏端口，仅用于展示，不用于认证。
- `token`：每台服务器独立的 256 位密钥。

修改配置后，在游戏内执行：

```text
/matrixbridge reload
```

服务器控制台不写 `/`：

```text
matrixbridge reload
```

## 4. 首次接入服务器

### 第一步：在 Minecraft 生成 token

游戏内由 OP 执行：

```text
/matrixbridge token generate
```

服务器控制台执行：

```text
matrixbridge token generate
```

插件会生成 64 位十六进制 token、写入 `config.yml` 并尝试重新连接。游戏内
显示的 token 可以点击复制。登记完成前出现认证失败或自动重连属于正常现象。

### 第二步：在机器人后台登记

连接后端服务器：

```bash
ssh -p <SSH端口> <SSH用户>@<服务器地址>
```

以生存服为例：

```bash
cd /opt/matrix-serverchat

docker compose exec matrix-serverchat \
  python -m app.admin add-server \
  --id survival \
  --name 生存服 \
  --group main \
  --port 25565 \
  --prompt-token
```

出现提示后粘贴插件生成的 token 并回车。输入不会回显，也不会进入 shell
命令历史。数据库只保存 SHA-256 哈希，之后无法反查明文 token。

### 第三步：确认连接

Minecraft 控制台：

```text
matrixbridge status
```

后台：

```bash
cd /opt/matrix-serverchat
docker compose exec matrix-serverchat python -m app.admin list-servers
docker compose logs --tail=100 matrix-serverchat
```

Matrix 房间：

```text
!server info survival
```

## 5. Token 轮换与泄露处理

发现 token 泄露或需要定期轮换时：

1. 在对应 Minecraft 控制台执行：

```text
matrixbridge token generate
```

2. 在后台执行：

```bash
cd /opt/matrix-serverchat
docker compose exec matrix-serverchat \
  python -m app.admin set-token --id survival
```

3. 粘贴新 token 并回车。
4. 使用 `matrixbridge status` 确认自动重连。

插件生成新 token 后到后台登记完成前会短暂离线。旧 token 在后台轮换后失效，
旧连接会在下一条应用消息时被拒绝。

禁止把 token：

- 发到 Matrix 房间；
- 写进共享文档或截图；
- 直接作为 SSH 命令参数；
- 提交到 Git 仓库。

## 6. Matrix 多管理员操作

`!` 和 `#` 前缀均可使用。

### 首次登记管理员身份

第一个管理员必须由后端主机管理员通过 SSH 登记，不能在聊天室自行提权。
把示例 ID 换成管理员真实的完整 Matrix ID：

```bash
cd /opt/matrix-serverchat
docker compose exec matrix-serverchat \
  python -m app.admin add-admin \
  --matrix-id '@name:matrix.example.org' --role owner
```

确认名单：

```bash
docker compose exec matrix-serverchat python -m app.admin list-admins
```

管理员角色分为：

- `owner`：服务器管理，以及增加、修改、移除管理员身份；
- `admin`：服务器管理，不能维护管理员身份。

建议登记至少两名可信 `owner`，避免唯一 owner 账号不可用。系统会拒绝删除
或降级最后一名 owner。

### 在聊天室维护管理员

```text
!admin list
!admin add @helper:matrix.example.org admin
!admin add @owner2:matrix.example.org owner
!admin remove @helper:matrix.example.org
!admin help
```

`list/help` 可由已鉴权的 owner 或 admin 使用，`add/remove` 只有 owner 可用。
`#admin` 写法与 `!admin` 相同。身份判断使用 Matrix 事件中的真实 sender，
不使用可伪造的显示昵称。

紧急情况下也可以从 SSH 控制台撤销身份：

```bash
docker compose exec matrix-serverchat \
  python -m app.admin remove-admin \
  --matrix-id '@name:matrix.example.org'
```

### 查看服务器

```text
!server list
!server info survival
!server status survival
!server help
```

列表字段依次包含服务器 ID、显示名称、路由组、端口、连接状态和启用状态。
整个 `server` 命令族（包括 `list`、`info` 和 `help`）都需要通过管理员双重
鉴权，普通成员无法借此查看内部服务器信息。

### 修改显示名称

```text
!server rename survival 新生存服
```

这个名称是管理员覆盖值，优先于插件中的 `server-name`。恢复插件配置名称：

```text
!server reset-name survival
```

### 修改展示端口

```text
!server port survival 25566
```

恢复插件上报的 `game-port`：

```text
!server reset-port survival
```

此端口仅用于管理和展示，不是 WebSocket 认证依据。

### 修改路由组

```text
!server group survival main
```

修改路由组后，还必须同步修改该服务器插件的：

```yaml
bridge:
  relay-group: "main"
```

然后执行 `matrixbridge reload`。插件配置和后台路由组不一致时，插件会拒绝
跨服消息，以防止错误路由。

### 启用与禁用

```text
!server disable survival
!server enable survival
```

禁用后，后台停止向该服务器转发消息并拒绝其后续应用消息。禁用不会删除
服务器、token、绑定或审计记录。

### 查看审计

```text
!server audit survival
!server audit
```

审计记录包含操作者 Matrix ID、服务器 ID、操作、修改前后值和时间。Matrix
事件 ID 也用于防止同一管理指令被重复执行。

## 7. Matrix 用户功能

```text
!help       查询可用指令及用法
#help       同上
!bind       获取绑定验证码
#bind       同上
!list       查看在线玩家
#list       同上
#online     获取各服在线榜 PNG（#在线榜 等价）
#game help  查看跨聊天室/游戏服的小游戏玩法
```

`help` 会根据查询者身份动态生成内容。普通成员只看到公共指令；通过双重鉴权的
admin 会看到服务器管理指令；owner 还会看到管理员身份维护指令。

机器人对 `#` 或 `!` 命令的回复默认进入该命令的 Matrix 消息列（线程），避免
帮助、服务器列表和管理结果刷满主时间线。`#list` 从多台服务器异步返回的在线
名单也会进入同一个消息列。在线程中继续发命令时，机器人会沿用原线程。普通
聊天和 Minecraft 事件不受影响。未绑定提醒固定留在主时间线，避免被忽略；
不支持线程的旧客户端可能显示兼容回退消息。

验证码十分钟有效。玩家随后在游戏执行：

```text
/matrixbind 验证码
```

Matrix 机器人指令不要使用 `/`，以免与 Matrix 客户端原生命令冲突。

聊天室与游戏聊天框都可使用 `#game roll`、`#game coin`、
`#game guess start`、`#game guess <1–100>` 和 `#game guess status`。
同一转发组的玩家共用一局猜数字，15 分钟后过期；结果在该组聊天室与已连接
游戏服显示，帮助与错误只回复发起者。机器人重启会结束未完成的游戏。
`#online`/`#在线榜` 是聊天室指令：后端最多等各服 5 秒，生成图片并在命令
消息列回复；未连接、超时或停用的服也会在榜中标注。同一用户限每 15 秒查询
一次。新版浅色榜单按服务器分组，玩家按累计游玩时长排序，显示缓存头像、
游戏 ID、累计时长和当前在线/离线状态，每服最多显示前 60 名。累计值来自
游戏服持久化的玩家统计，机器人、插件或服务器重启不会清零。要显示历史榜
和准确时长，须同时更新各 Minecraft 服务器的插件；旧插件仍能被查询，但
只能列当前在线玩家且时长显示 `—`。小游戏中的 Matrix 玩家优先显示绑定的
游戏 ID，未绑定才用聊天室昵称。

## 8. 离线服与 AuthMe

离线服即使安装 AuthMe，也应使用：

```yaml
BINDING_MODE: "scoped"
```

AuthMe 验证的是服务器本地账号密码，不会把离线 UUID 变成 Mojang 正版 UUID。
玩家应先 `/login`，再执行 `/matrixbind`。确保 AuthMe 未登录状态不允许执行
`/matrixbind`。

只有所有服务器都开启正版验证，并能保证 UUID 在各服一致时，才使用：

```yaml
BINDING_MODE: "online_uuid"
```

修改位置为 `/opt/matrix-serverchat/compose.yaml`，修改后执行：

```bash
cd /opt/matrix-serverchat
docker compose up -d
```

## 9. 提及和同名玩家

游戏玩家发送：

```text
@Steve 该你上线了
```

如果 Steve 已绑定，Matrix 中会产生标准提及通知。

同一组不同服务器存在同名玩家时，使用限定写法：

```text
@vanilla:Steve
@survival:Steve
```

Matrix 房间中使用客户端原生 `@` 提及用户。消息进入游戏后，已绑定的长
Matrix ID 会替换为游戏 ID；离线服跨服身份可能显示为 `@vanilla:Steve`。

## 10. 一键部署和更新

在开发电脑 PowerShell 中：

```powershell
cd "C:\path\to\serverchatbot"

powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\deploy-0.4.9.ps1
```

脚本会：

- 上传后端和远端安装脚本；
- 备份 SQLite 数据库；
- 重建机器人容器；
- 保留 `.env`、Matrix 密码和数据库；
- 安装并启用 systemd 开机启动（系统支持时）。

插件 JAR 需要另行复制到每台 Minecraft 服务器的 `plugins` 目录。替换旧 JAR
时保留 `plugins/MatrixChatBridge/config.yml`，然后重启对应游戏服。

SSH 密码由 OpenSSH 交互读取，不会写入部署脚本。

## 11. 日常检查

### 开机自动启动与持久化

机器人后台采用两层恢复机制：

- Compose 中的 `restart: unless-stopped` 负责容器进程异常退出后的自动拉起；
- systemd 负责主机关机或重启后，等待 Docker 和网络就绪，再启动
  `/opt/matrix-serverchat` 中的机器人服务。

使用 GitHub 发行版文件在 Ubuntu 上安装时执行：

```bash
sudo bash install-0.4.9.sh matrix-serverchat-backend-0.4.9.tar.gz
```

脚本会安装并启用：

```text
/etc/systemd/system/matrix-serverchat.service
```

安装后检查：

```bash
systemctl is-enabled matrix-serverchat
systemctl is-active matrix-serverchat
systemctl status matrix-serverchat --no-pager
```

正确结果应包含：

```text
enabled
active
Active: active (exited)
Container matrix-serverchat Running
```

`active (exited)` 是正常状态，不表示机器人已经退出。这个 unit 使用
`Type=oneshot` 和 `RemainAfterExit=yes`：systemd 只负责执行
`docker compose up -d`，机器人随后由 Docker 在后台运行。

继续确认容器运行状态和自动重启策略：

```bash
docker inspect -f '{{.State.Status}} / restart={{.HostConfig.RestartPolicy.Name}}' \
  matrix-serverchat
```

预期输出：

```text
running / restart=unless-stopped
```

日常启停和重启应优先使用：

```bash
systemctl start matrix-serverchat
systemctl stop matrix-serverchat
systemctl restart matrix-serverchat
```

重启后可在 Matrix 房间发送 `#ping`，确认机器人监听 8766，且各 Minecraft
服务器均为“连接正常”。新版 `#ping` 还会实测机器人↔插件的查询往返耗时，
并显示在线玩家的游戏 ping、1 分钟 TPS 和 MSPT。往返耗时包含游戏服主线程
排队，不是纯网络 ping；超过 3 秒显示超时。旧插件未提供的新指标显示
“未提供”，更新各服插件后才会出现玩家 ping、TPS、MSPT。

新版插件会在 Minecraft 服务端正常关闭或重启前主动通知机器人。聊天室会先
收到“服务器正在关闭或重启”，同一服务器 ID 重新完成握手后收到“服务器重启
成功”。两条通知都进入主时间线且各发送一次。正常停服不会再叠加连接异常
警报；强制结束进程、主机断电或网络故障来不及发送停服信号，仍按连接异常
规则延迟通报。只更新机器人、不更新插件时无法识别正常停服。

如果 systemd 日志提示 `Found multiple compose files`，先查看实际文件：

```bash
cd /opt/matrix-serverchat
ls -la *compose*.y*ml
systemctl status matrix-serverchat -l --no-pager
```

只要日志显示选定配置后容器成功进入 `Running`，该警告不会影响当前运行。未经
核对不要直接删除 Compose 文件；先确认 systemd 的 `WorkingDirectory` 是
`/opt/matrix-serverchat`，并确认实际使用的是该目录中的 `compose.yaml`。

持久化 unit 只管理 Compose 服务 `matrix-serverchat`，不会使用
`--remove-orphans`，也不会停止、删除或修改占用 8765 的原桥接机器人。如果
管理员曾手动执行 `docker compose stop`，应使用
`systemctl restart matrix-serverchat` 恢复运行。

### 为每日网络重启设置静默时段

使用包含每日静默功能的后端版本。若线上 `compose.yaml` 已经定制，在现有
`matrix-serverchat` 服务的 `environment:` 中设置以下四项，已有同名项时修改原值。
这样可以保留原有端口和挂载。
这个例子只静默 `survival` 服，覆盖 UTC+8 每天早上 06:00 的网络重启。

```yaml
      SERVER_HEALTH_QUIET_START: "05:55"
      SERVER_HEALTH_QUIET_END: "06:15"
      SERVER_HEALTH_QUIET_TIMEZONE: "Asia/Shanghai"
      SERVER_HEALTH_QUIET_SERVER_ID: "survival"
```

```bash
cd /opt/matrix-serverchat
docker compose config --quiet && docker compose up -d --build matrix-serverchat
docker compose exec -T matrix-serverchat printenv \
  SERVER_HEALTH_QUIET_START SERVER_HEALTH_QUIET_END \
  SERVER_HEALTH_QUIET_TIMEZONE SERVER_HEALTH_QUIET_SERVER_ID
```

窗口内断开又恢复时，群里会跳过这次断线和恢复通知；窗口结束时仍断开才会
告警。自动重连和 `#ping` 照常运行。为了验证实际效果，网络恢复后运行
`docker compose logs --since 30m matrix-serverchat`，对照日志中的断开、重连
时间与 Matrix 房间消息。用于验证的断线应超过平时的告警延迟。

## 12. 常见故障

### `Unauthorized` 或关闭码 4001

原因通常是：

- `server-id` 未登记；
- 插件 token 与后台哈希不匹配；
- 服务器已被禁用；
- token 已轮换但另一端没有更新。

处理：重新执行“Token 轮换”流程，不要尝试找回旧 token。

### `unsupported protocol version`

后端和插件版本不一致。确认双方均为 0.4.9/v2。

### `address already in use`，端口 8766 被占用

```bash
docker ps --filter publish=8766
ss -lntp | grep 8766
```

先确认端口占用者，再决定是否调整端口或停止对应服务。不要直接使用
`--remove-orphans`，因为同机还可能运行占用 8765 的其他桥接机器人。

### Matrix 同步持续超时

确认 homeserver 配置必须是：

```yaml
MATRIX_URL: "https://matrix.example.org"
```

检查连通性：

```bash
curl -fsS --connect-timeout 10 --max-time 20 \
  https://matrix.example.org/_matrix/client/versions
```

### 跨服消息不出现

依次检查：

1. 两台服务器均已连接且启用；
2. 后台登记的 `relay_group` 相同；
3. 两台插件配置的 `bridge.relay-group` 与后台一致；
4. 消息来自真实玩家聊天，不是命令或机器人转发消息。

## 13. 数据与备份

持久数据位于：

```text
/opt/matrix-serverchat/data/bridge.db
```

其中保存：

- 服务器注册和 token 哈希；
- Matrix 与 Minecraft 绑定；
- Matrix 管理员身份及其角色；
- Matrix 登录和同步位置；
- 最近处理的消息 ID；
- 管理审计记录；
- 玩家头像索引、刷新状态及 Matrix 媒体地址。

玩家头像 PNG 位于 `data/avatars/`。不要删除 `data/` 或
`secrets/matrix_password`。更新容器不会清除这些挂载数据。

建议在重大更新前使用 SQLite 在线备份；一键部署脚本会自动执行。恢复数据库
属于停机操作，应先停止机器人容器并确认备份文件，再由后端主机管理员处理。

## 14. 玩家头像缓存

机器人会在 Minecraft 消息正文开头显示玩家头部小图标。头像处理完全位于
机器人后端，插件端无需修改，也无需重启 Minecraft 服务端。

处理规则如下：

1. 后端按玩家 ID 查询 Mojang 玩家档案和皮肤；
2. 截取皮肤的脸部和帽子层，生成 32×32 PNG；
3. PNG 保存在 `/opt/matrix-serverchat/data/avatars/`；
4. Matrix 媒体地址及刷新状态保存在 `data/bridge.db`；
5. 新玩家第一次发言或查询失败时显示内置 Steve 头像；
6. 获取失败的玩家会在下一次产生游戏事件时重试；
7. 已成功缓存的旧头像不会因一次刷新失败而丢失；
8. 每周日北京时间 00:00 自动刷新所有已见玩家。

查看头像处理日志：

```bash
cd /opt/matrix-serverchat
docker compose logs --tail=200 matrix-serverchat | grep -E '头像|avatar'
```

临时关闭头像功能时，在 `compose.yaml` 中设置：

```yaml
AVATAR_ENABLED: "false"
```

然后只重建机器人容器：

```bash
docker compose up -d --no-deps --force-recreate matrix-serverchat
```

不要删除 `data/avatars/` 或 `bridge.db`，否则本地 PNG 或 Matrix 媒体索引会
重新建立。即使 Matrix 客户端不支持正文图片，消息的纯文本内容仍然存在。

Matrix 用户发送的媒体不会由机器人下载到 Minecraft 服务端。游戏内只显示
简短类型标识：`[图片]`、`[视频]`、`[语音]`、`[文件]` 或 `[贴纸]`。贴纸的
文件名、媒体地址和文件大小不会进入游戏聊天；发送者名称仍会转换为其绑定的
玩家 ID。

## 15. 建议置顶的玩家说明

```text
🎮 Minecraft ↔ Matrix 聊天互通说明

本房间的普通消息会同步到 Minecraft，同一聊天组内的服务器聊天也会互通。

账号绑定：
1. 在房间发送 !bind 或 #bind

提及用户：
• Matrix 中使用客户端自带的 @ 提及
• 游戏中使用 @玩家ID
```
